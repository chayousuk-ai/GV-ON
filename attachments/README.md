## AI 지시문 (AI가 읽는 부분)

당신은 마케팅 업무 전용 브라우저의 설계·구현 총괄이다. 첨부한 `광고업무_전용브라우저_요구사항(AI용).md`를 단일 기준으로 삼는다.

1. 먼저 MD의 1부(사용 환경)와 부록 A~F를 읽고, 기능 F1~F8을 기능 단위 상세 정의서와 개발 계획서로 나눠 작성해 제출한다. 각 정의서에는 화면·조작 순서·읽을 값·가드 조건·수용 기준을 포함한다.
2. 구현 순서는 MD §11의 단계를 따른다. 1단계(프로필·화면 세트·네이버 애널리틱스 값 추출)를 단독 배포 가능한 상태로 먼저 완성한다.
3. 다음은 임의로 바꾸지 않는다: 1부 사용 환경 정의 전체, F2 액션 스킬, F3 기간 가드, F4 비용 경고, 보안 원칙 S1~S10, 부록 F 계정 매칭. 바꿔야 한다고 판단되면 이유를 적어 먼저 묻는다.
4. 자격 증명은 Windows 자격 증명 관리자의 'GV/매체/브랜드/역할' 항목명으로만 참조한다. 어느 항목이 어느 계정·어느 광고비 열인지는 `광고계정_금고매칭표(비밀정보 없음).xlsx`의 "3자 매칭" 시트를 따른다. 어떤 코드·로그·출력에도 비밀값을 남기지 않는다.
5. 화면 조회·값 읽기는 자동 실행하되, 광고비가 실제로 움직이는 변경(입찰가·ON/OFF·결제)은 반드시 사람 승인 단계를 둔다.
6. 외부 클라우드 AI와의 통신은 MD S7 단일 통로만 사용하고, 화면 캡처 중에는 S10 배너·중단 스위치를 구현한다.
7. 값이 없으면 null로 두고 보고한다. 다른 기간 값 대입·추정 금지.
8. 부록 D의 사고 사례 T1~T12를 자동 테스트로 만들어 매 빌드마다 통과시킨다.
9. 플랫폼은 Windows 11 우선. Chromium 계열 커스텀 셸을 쓰고 브라우저 엔진은 새로 만들지 않는다. 로컬 에이전트(헤르메스)·서버 DB 연동은 로컬 통신만 쓴다.
10. 막히는 변수가 생기면 30분 단위로 담당자에게 질문하고, 질문에는 '무엇이 막혔고, 두 가지 선택지와 각 장단점'을 비개발자가 이해할 말로 쓴다.
11. 작업 기록·추출값은 로컬 Qdrant에 적재해 자연어 검색이 가능하게 한다.

산출물: (1) 기능별 상세 정의서, (2) 개발 계획서(단계·담당·수용 기준), (3) 1단계 실행 파일과 테스트 결과.
